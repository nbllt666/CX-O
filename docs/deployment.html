🖥️ 环境要求

显存分配策略（单卡 20GB 场景）

单卡跑全部服务时显存比较紧张。推荐策略：把 GPU 留给当前对话必须的模型，LLM 约 18GB、CosyVoice TTS 约 10GB。如果显存不够，优先保证 LLM + ASR，TTS 可走备用引擎兜底，或关掉暂时不用的服务。

📦 模型下载

CX-O 依赖多个 AI 模型，按下面的清单逐一下载。分为对话模型、语音模型、向量嵌入模型三类。

对话模型

LLM 大语言模型（通过 Ollama 拉取）

这是 AI 角色对话的核心模型。通过 Ollama 拉取，默认配置使用 qwen3-vl:8b。

模型 用途 下载命令 大小
qwen3-vl:8b 主对话 / 摘要 / 记忆处理（三个槽位默认都用它） ollama pull qwen3-vl:8b ~5GB
nomic-embed-text 记忆向量嵌入（语义搜索） ollama pull nomic-embed-text ~270MB

可选：使用 vLLM / TRT-LLM 替代 Ollama

如果需要更高性能，可以用 vLLM 或 TRT-LLM 替代 Ollama。vLLM 支持 GGUF 格式模型直接加载，TRT-LLM 需要预构建引擎。配置方式见 配置指南。

语音模型

ASR / TTS / 降噪模型（通过下载脚本）

语音相关模型通过项目自带的下载脚本获取，默认下载到 models/ 目录。

模型 用途 下载命令 大小 目标路径
VoxCPM2
OpenBMB/VoxCPM2		 VoxCPM 语音合成（语音工作站步骤一） python download_voxcpm2.py ~1.5GB models/VoxCPM2/
ZipEnhancer
iic/speech_zipenhancer_ans_multiloss_16k_base		 语音降噪 python download_voxcpm_support.py ~200MB models/zipenhancer_16k/
SenseVoiceSmall
iic/SenseVoiceSmall		 ASR 语音识别（本地内置模式） python download_voxcpm_support.py ~400MB models/SenseVoiceSmall/
TTS 语音合成模型

语音合成模型（主引擎 CosyVoice3）

TTS 以 CosyVoice3 为主引擎，VoiceDesign 与 Qwen3-TTS Base 作为备用与降级。主引擎需预下载模型后通过启动脚本加载。

模型 用途 获取方式
Fun-CosyVoice3-0.5B-2512 主引擎——克隆与情感合成 从 ModelScope 预下载到 models/Fun-CosyVoice3-0.5B-2512，用 start-cosyvoice.ps1 加载
VoiceDesign（Qwen3-TTS vLLM） 无参考音频时的音频设计 start-qwen3-tts.ps1 启动
Qwen3-TTS Base TTS 降级兜底 start-qwen3-base.ps1 + vLLM-Omni 启动

模型下载总量估算

全部模型下载约占 15-25GB 磁盘空间：Ollama 对话/嵌入模型 + VoxCPM2 + SenseVoice + CosyVoice3 等 TTS 模型。首次部署建议预留 100GB 以上。

🔌 配套服务

CX-O 运行依赖以下外部服务。其中 Ollama 是必须的，Weaviate 按功能需求启用。

必须

Ollama — 本地 LLM 推理

CX-O Server 启动时会连接 Ollama 加载对话模型和嵌入模型。不启动 Ollama，后端无法正常工作。

默认地址http://localhost:11434
端口11434
安装方式从 ollama.com 下载安装包
启动命令ollama serve（安装后默认作为服务运行）
配置位置config/default.yaml 第 30-31 行
推荐

Weaviate — 向量数据库

记忆系统的语义搜索依赖向量数据库。支持两种模式：独立服务或嵌入式。

默认端口HTTP 8090 / gRPC 50061
独立服务启动Docker: docker run -p 8090:8090 semitechnologies/weaviate
嵌入式模式配置 vector_backend: weaviate_embedded，无需独立服务，自动嵌入进程
配置位置config/default.yaml 第 100-107 行

注意

虽然 default.yaml 中列出了 Chroma、Milvus Lite、Qdrant 等后端，但后端代码当前仅支持 weaviate 和 weaviate_embedded 两种。配置其他后端不会生效。

内置

知识图谱 — SQLite 图存储

知识图谱基于内置 SQLite 图存储（data/graph.db），无需额外安装图数据库服务。可选接入 Weaviate 做向量增强。

存储位置data/graph.db
启动方式内置，随后端自动初始化（图数据 lazy 初始化，首次调用时创建）
关闭方式设置 graph_enabled: false
内置

SQLite — 主业务数据库

主业务数据存储在 SQLite 文件中，无需额外安装服务。包括 data/cxhms.db（主库）、data/memories.db（记忆库）、data/sessions.db（会话库）等。

🚀 启动顺序

服务有依赖关系，必须按正确顺序启动。下面是完整的启动流程。

完整启动流程

  1. 基础环境准备
    # 创建 Python 虚拟环境
cd c:\CX-O
.\create-env.bat
call py311\Scripts\activate.bat

# 前端依赖
cd APP-Frontend
npm install
  2. 拉取所有模型
    # Ollama 模型
ollama pull qwen3-vl:8b
ollama pull nomic-embed-text

# 语音模型
python download_voxcpm2.py
python download_voxcpm_support.py

# TTS 主引擎模型（按部署文档「模型下载」章节准备 CosyVoice3 等）
  3. 启动基础设施服务
    # Ollama（必须最先启动）
ollama serve

# Weaviate（如需向量搜索）
docker run -d -p 8090:8090 -p 50051:50051 semitechnologies/weaviate
  4. 启动推理服务（可选，按需启动）
    # ASR 语音识别（Docker）
docker compose up -d asr-sensevoice

# TTS 语音合成（主引擎 CosyVoice3，独立 conda 服务）
cd docker\llm
.\start-cosyvoice.ps1

# LLM（如不用 Ollama，用 vLLM 替代）
docker compose up -d llm
  5. 启动 CX-O 应用服务
    # 语音工作站（如需声音克隆功能）
cd CX-O-VoiceWorkStation
.\start.bat

# 后端服务（核心，必须启动）
cd CX-O-SERVER
.\start.bat

# 前端服务（必须启动，浏览器模式）
cd APP-Frontend
.\start.bat browser
  6. 访问应用
    浏览器打开 http://localhost:3100，首次访问会引导确认后端连接。

关键依赖关系

服务 依赖 说明
CX-O Server Ollama 启动时连接，失败则 LLM 客户端为空
CX-O Server Weaviate vector_enabled=true 时连接，失败抛异常
CX-O Server ASR / TTS Remote asr.mode=remote / tts.mode=remote 时不加载本地模型
CX-O Server CosyVoice3 TTS tts.mode=remote 时启动会发预热请求到 8094 端口
CX-O Frontend CX-O Server 启动时请求 /health 检查后端连通性

⚙️ 配置指南

CX-O 的配置分三层：配置文件、环境变量、前端设置。优先级从高到低。

配置文件：config/default.yaml

主配置文件，包含所有核心配置项。修改后重启后端生效。

配置项 默认值 说明
server.port 8000 后端服务端口
models.main.model qwen3-vl:8b 主对话模型
models.main.provider ollama 模型接入方式（ollama / vllm / trtllm）
memory.vector_backend weaviate 向量数据库后端
memory.vector_enabled true 是否启用向量搜索
memory.graph_backend sqlite 图数据库后端（sqlite / weaviate）
memory.graph_enabled true 是否启用知识图谱
asr.mode remote ASR 模式（embedded / remote）
tts.mode remote TTS 模式（remote 远程合成）
tts.engine cosyvoice TTS 引擎（cosyvoice 主 / voicedesign / qwen3_base 降级）
tts.remote_url http://127.0.0.1:8094 CosyVoice3 主引擎地址

🐳 Docker 部署

推理服务通过 Docker Compose 编排，按需启动。

Docker Compose 服务一览

服务名 用途 容器端口 → 宿主端口 GPU
asr-sensevoice ASR 语音识别（FunASR + SenseVoice） 8005 → 8005 CPU（无空余 GPU）
llm LLM 推理（vLLM 或 TRT-LLM） 8080 → 8080 GPU

Docker Compose 现仅编排 ASR 与 LLM 推理服务；TTS 语音合成走独立服务（CosyVoice3 / VoiceDesign / Qwen3-TTS Base），不在此编排内。

可选 · 自我进化

CXO-Tuner — 进化实验室（可选服务）

CXO-Tuner 是"自我进化"能力的独立可选服务。AI 会从你们的日常对话里自动学习你的偏好，在离线闲时悄悄变聪明。不启用时对主系统零影响。

项目 说明
启动方式docker compose --profile tuner up（默认 docker compose up -d 不含此服务）
端口8300（可用 CXO_TUNER_PORT 调整）
硬件支持 GPU 与 CPU——训练默认走 CPU，注入 GPU 编号（CUDA_VISIBLE_DEVICES）即 GPU 加速。推荐有独立空余 GPU 时启用
挂载数据 / 模型 / 角色卡目录卷挂载（对话数据、训练产物 LoRA adapter）
可选性仅当启用 tuner profile 时才启动；关闭即完全隔离，主系统不依赖其任何产物

怎么用

在设置 → 进化实验室开启能力，然后用 docker compose --profile tuner up 拉起该可选服务。之后正常陪伴、正常聊天即可，系统会在闲时自动学习、不断优化。

常用 Docker 命令

# 启动所有推理服务
docker compose up -d

# 仅启动 ASR
docker compose up -d asr-sensevoice

# 仅启动 LLM（指定后端）
LLM_BACKEND=vllm docker compose up -d llm
LLM_BACKEND=trtllm docker compose up -d llm

# 查看服务状态
docker compose ps

# 查看日志
docker compose logs -f llm

# 停止所有服务
docker compose down

❓ 常见问题

部署和运行中常见的问题排查。

后端启动报错连不上 Ollama

确认 Ollama 服务在运行（ollama serve 或检查系统服务）。默认地址 http://localhost:11434。确保 qwen3-vl:8b 和 nomic-embed-text 都已拉取（ollama list 查看）。

语音对话没声音

语音对话依赖 ASR 和 TTS 两个独立服务。默认配置走远程模式（asr.mode=remote + tts.mode=remote），需要：

  • 启动 ASR 服务：Docker docker compose up -d asr-sensevoice（端口 8005）
  • 启动 TTS 服务：根据 tts.engine 配置启动对应服务
  • 检查 config/default.yaml 中的 asr.remote_url 和 tts.remote_url 是否指向正确地址

CosyVoice TTS 首次请求很慢

这是冷启动问题。后端启动时会自动发预热请求（非流式 + 流式双重预热），但如果 CosyVoice 服务刚启动还没就绪，预热会失败。等待 TTS 服务就绪（http://127.0.0.1:8094 可访问）后重启后端即可。

显存不足（OOM）

单卡跑全部服务时显存可能不够。解决方案：

  • 降低 LLM 的 gpu_memory_utilization（如 0.9 → 0.7）
  • 把 embedding 与 TTS 放到同一块 GPU、ASR 走 CPU，合理分卡
  • 关闭不用的服务（如暂时不直播就关掉相关源）
  • 使用嵌入式 Weaviate 替代独立服务节省内存

前端连接不上后端

检查 APP-Frontend/.env 中的 VITE_API_URL 是否指向正确的后端地址。默认 http://127.0.0.1:8000。前端启动时会请求 /health 接口检查连通性，连不上会显示引导页。

端口冲突

如果某个服务端口被占用，可以在 .env 或 config/default.yaml 中调整对应端口，并同步更新其他服务的引用地址。主要服务端口见端口分配表。

Weaviate 连接失败

两种解决方案：1）启动独立 Weaviate 服务；2）改用嵌入式模式，设置 memory.vector_backend: weaviate_embedded，无需独立服务。如果不需要向量搜索，设置 memory.vector_enabled: false 关闭。

ModelScope 下载慢

语音等模型下载脚本使用 ModelScope（阿里云），国内网络通常较快。如果仍然慢，检查网络代理设置；从 HuggingFace 下载时可设置 HF_ENDPOINT=https://hf-mirror.com 使用镜像站。
