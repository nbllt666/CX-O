# modules/ — AC 范式模块容器

> 本目录为 AC 范式 v6 标准模块区（rules-2 §二），按「模块{N}_{中文名}」命名，N 从 0 递增。

## 当前状态：空容器

本目录于 2026-07-02 由 AC v6 治理层对齐任务创建，当前为空容器，预留给未来按 AC 规范新增的模块。

## CX-O 服务边界声明

**CX-O 现有服务不迁移至本目录**。CX-O 是多服务架构，以下服务目录留根级不动：

| 服务 | 根级目录 | 技术栈 | 定位 |
|------|---------|--------|------|
| CX-O Frontend | `CX-O-Frontend/` | React + TypeScript + Vite + Electron | Web 前端 + 桌面宠物 |
| CX-O Server | `CX-O-SERVER/` | Python + FastAPI + WebSocket | 单体后端 |
| CX-O VoiceWorkStation | `CX-O-VoiceWorkStation/` | Python | 语音工作站（可选） |

这些服务是**独立服务**，不是 AC 模块。它们之间仅通过 `public/` 三层契约通信。

## 模块命名规范（rules-2 §二）

未来新增模块必须遵循命名格式：`模块{N}_{中文名}`

- N 为阿拉伯数字，从 0 开始递增
- 数字前缀保证 IDE 中按依赖顺序排序
- 中文名称明确模块核心职责
- 模块数量不做固定限制，按需拆分

示例：
- `模块0_全局调度面板/`
- `模块1_数据锚点与存储模块/`
- `模块2_核心业务引擎模块/`

## 何时在本目录新增模块

仅当新增的功能满足以下条件时，才在本目录创建 AC 风格模块：
1. 功能是 CX-O 后端单体的一部分（而非独立服务）
2. 功能需要与其他模块通过 `public/` 契约协作
3. 已通过 s0203（拓扑化模块拆分）Skill 完成依赖 DAG 分析

新增模块前必须：
- 调用 s0203 做模块拆分与编排
- 调用 s0301 生成模块级 AGENTS.md
- 在 `public/interface_stub/` 下定义模块对外接口契约
