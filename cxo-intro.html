Project Overview

项目概览

CX-O 是一个 AI 虚拟主播 / 助手平台，由五个核心子项目组成，采用前后端分离 + 单体后端架构，通过 WebSocket 与 HTTP 双通道实现实时通信。

Core Intelligence

核心智能

记忆、图谱、多模型路由、上下文管理与提示词构建，构成 CX-O 的智能底座。

1

智能记忆系统

server/core/memory/

模拟人类记忆机制的对话记忆管理解决方案，采用 SQLite + Weaviate + LLM 混合架构。MemoryManager 为单例模式，统一管理记忆生命周期。

  • 双阶段指数衰减：T(t) = α·e^(-λ₁·Δt) + (1-α)·e^(-λ₂·Δt)，模拟艾宾浩斯遗忘曲线
  • 三维评分：重要性 × 权重 + 时间 × 权重 + 相关性 × 权重
  • 场景感知路由：7 种场景（task/chat/recall/learning…）动态调整权重
  • 混合搜索：向量搜索（0.6）+ 关键词搜索（0.4）
  • 再激活加成：召回时提升时间分数，模拟记忆强化
  • 多 Agent 隔离：每个 Agent 独立记忆空间（agent_id）

记忆类型与衰减

short_term快速衰减
long_term正常衰减
permanent不衰减 · 1.0

2

知识图谱集成

server/core/graph/

语义图数据库系统，SQLite + Weaviate 混合架构，GraphDatabase 为主入口，集成 NodeManager / EdgeManager / TraversalManager / SemanticSearch。

  • 四类图谱：User（用户关系）、Thing（事物关系）、Concept（概念知识）、Event（事件关系）
  • 图算法：BFS、DFS、Dijkstra 最短路径、PageRank、LPA/Louvain 社区发现
  • 混合查询：(1-w)·结构分 + w·语义分
  • 56 个图工具：每类图谱 14 个工具，供主模型/摘要模型/记忆 Agent 调用

每类图谱 14 工具

create_entity create_relation query_entities find_paths search_related_memories extract_entities merge_entities get_entity_summary update / delete update / delete_relation get_stats · export

多模型路由与 LLM 客户端

server/core/model_router.py · server/core/llm/

统一管理多 LLM 模型的路由分发，支持 Ollama 与 vLLM 两种后端。

  • 三种角色：main（核心对话）/ summary（摘要）/ memory（记忆管理）
  • 模型跟随：summary/memory 可跟随 main，避免重复加载
  • 模型预热：启动时自动预热，减少首次响应延迟
  • 状态检测：实时检测模型可用性与延迟

上下文管理 & 提示词构建

server/core/context/ · server/services/prompt_builder.py

ContextManager 管理会话与消息历史，支持工作空间级隔离；Mono 上下文机制允许信息在指定轮次内保持，自动过期清理。

  • Mono 上下文：临时性上下文保持，按 rounds 过期

  • HiddenPromptManager：系统级指令对用户不可见，自动追加到 system 消息
  • 标记清理：发送给 LLM 前自动去除情感/音效标记

Safety & Interaction

内容安全与交互控制

三档防火墙、双向全双工打断、情感与音效解析引擎，保障直播与对话的安全与表现力。

🛡️

三档防火墙

直播弹幕审核决策系统，规则过滤 + LLM 智能决策双层防护。

  • block：违规内容直接拦截
  • passive：正常弹幕放行不回复
  • reply：优质弹幕互动回复
  • LLM 不可用时默认放行，避免误伤
  • V3 支持 ASR 打断（main_llm / independent_llm）
🔄

全双工打断系统

双向打断能力，InterruptManager 单例统一管理。

  • 用户打断 Agent：ASRInterruptModule 停止 TTS
  • Agent 打断用户：AgentInterruptUser 智能插话
  • LLM 判断是否需要打断（非简单规则）
  • 冷却时间 + 最小语音时长限制
  • voice.dual_stream 双流式语音
💬

情感与音效解析

统一标记语法，多端联动驱动 TTS 与虚拟形象表情。

  • [emotion:name] 15 种情感标记
  • [effect:name] 音效标记（wav/mp3/ogg/flac）
  • happy/sad/angry/surprised/fear/disgust/excited…
  • FrontendMarker + MarkerAdapter 前端适配
  • 情感标记同时驱动 TTS 与表情
Voice Capabilities

语音能力

从识别到合成，从检测到工作站，构建完整的语音定制流水线。

🎙️

ASR 语音识别

双模式架构：embedded（SenseVoice 本地推理）/ remote（HTTP 远程），embedded 加载失败自动降级为 remote。SenseVoiceStreamingClient 支持增量流式识别，适配实时对话。

SenseVoice · 自动降级
🔊

TTS 语音合成

三模式：embedded（F5-TTS）/ remote（HTTP）/ orpheus（vLLM + SNAC）。情感语音切换、音效插入、按句分割流式合成、Triton 推理加速。

F5-TTS · Orpheus · Triton
📡

VAD 语音活动检测

三种模式：Energy（能量阈值）/ WebRTC（轻量高效，默认）/ Silero（神经网络，最准确）。高级模式不可用时自动降级，语音开始/结束事件回调驱动打断与口型同步。

Energy · WebRTC · Silero
🎵

Orpheus TTS 流式情感合成

基于 vLLM + SNAC 解码，OpenAI 兼容 API（/v1/audio/speech）。客户端 → FastAPI Bridge (:5060) → vLLM → SNAC 7 层码本解码 → 24kHz WAV。首包延迟 < 300ms，RTF 约 0.08-0.15。

13 种音色：tara/leah/leo/dan/mia/jess/zoe/zac/river/charlotte/james/matthew…
情感标签：<laugh> <sigh> <giggle> <cough> <gasp> 等

vLLM · SNAC · 24kHz

语音工作站 · 五步工作流

CX-O-VoiceWorkStation · :8200

独立的语音工作站服务，提供从参考音频到最终推理的端到端语音克隆流水线，多引擎互补。

  • ① VoxCPM：参考音频生成（design / controllable_clone / ultimate_clone）
  • ② CosyVoice：情感参考音频（8 情感 + 56 过渡 = 64 参考音频，Instruct2 模式）
  • ③ So-VITS-SVC 预处理：音频切片、语音标注、特征提取
  • ④ So-VITS-SVC 训练：可配置 epochs/batch_size/lr，异步训练，支持 F5-TTS 微调
  • ⑤ So-VITS-SVC 推理 + IndexTTS 2：8 情感 × 5 强度 = 40 组合

IndexTTS 按需启停：IndexTTSManager 单例，空闲超时（默认 300s）自动停止，节省 GPU 资源。

Infrastructure

基础设施

WebSocket 实时通信、闹钟定时提醒、会话持久化，支撑系统稳定运行。

📡

WebSocket 实时通信网关

WebSocketManager 连接管理，频道订阅/发布模型，支持点对点、广播、频道广播、外部事件广播。Action Handler 路由：chat.* / memory.* / tools.* / voice.* / asr.* / tts.* / acp.* / mcp.* 等。离线回调保存上下文到长期记忆，30 分钟无活动自动断开。

⏰

闹钟/定时提醒系统

AlarmManager 基于 SQLite 持久化 + threading.Timer 精确触发。重启后自动恢复待触发闹钟，过期闹钟立即触发。状态机：pending → triggered / cancelled。shutdown 时取消所有定时器，防止回调异常。

💾

会话持久化存储

SessionStore SQLite 持久化会话与消息，通过 workspace_id 实现工作空间级隔离。cleanup.py 提供过期自动清理，支持配置过期时间与清理间隔。提供会话与消息统计查询。
